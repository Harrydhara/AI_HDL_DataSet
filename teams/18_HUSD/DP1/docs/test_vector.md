# Test Vectors & Signal Definitions

This document summarizes the input/output test vectors used to verify the **32-bit UART Controller** project. It covers the automated hardware vectors in `tb_main.v` and the signal interface for the advanced whitebox testing in `tb_custom.v`.

---

## 1. Automated Test Vectors (`tb_main.v`)
These vectors are hardcoded into the Verilog testbench and execute automatically on startup. They verify the core hardware logic without external software intervention.

| Vector # | Test Case Name | Input Stimulus (Driven by TB) | Expected Output (Verified by TB) | Logic Verified |
| :--- | :--- | :--- | :--- | :--- |
| **V1** | **System Reset** | `rst_n` transitions `0` $\to$ `1` | `uo_out` = `0x00` | [cite_start]Internal registers (e.g., `tx_reg`) are cleared; signals initialize to known states[cite: 25, 26]. |
| **V2** | **Adder Logic (Base)** | `ui_in` = `0x0A` (10) | `uo_out` = `0x0A` (10) | Combinational path: `uo_out = tx_reg + ui_in`. [cite_start]Since `tx_reg` is 0, Output equals Input[cite: 22]. |
| **V3** | **Adder Saturation** | `ui_in` = `0xFF` (255) | `uo_out` = `0xFF` (255) | [cite_start]Verifies the adder handles the maximum 8-bit value without unexpected overflow artifacts[cite: 22]. |
| **V4** | **External Interrupt** | `ui_in[6]` = `1` (High) | `uio_out[0]` = `1` (High) | [cite_start]Checks the "External Test Latch" logic which triggers an interrupt on `ui_in[6]` rising edge[cite: 33]. |
| **V5** | **UART RX Reception** | Serial Stream `0x55` on `ui_in[0]`<br>*(Start + 01010101 + Stop)* | `uio_out[0]` = `1` (High) | [cite_start]Verifies the UART Receiver correctly shifts in data and asserts the interrupt upon completion[cite: 32]. |

## 2. Advanced Signal Interface (`tb_custom.v`)
This testbench acts as a **Passive Harness**. It does not generate data itself but provides a bridge for Python (Cocotb) to drive inputs and "peek" at internal logic via Whitebox signals.

### A. Inputs (Driven by Python)
| Signal | Width | Description | Test Usage |
| :--- | :--- | :--- | :--- |
| **`clk`** | 1 | System Clock | Generated by harness (100 MHz). |
| **`rst_n`** | 1 | Active-Low Reset | [cite_start]Toggled to initialize the DUT[cite: 3, 48]. |
| **`ena`** | 1 | Enable | Set to `1` to activate the design. |
| **`ui_in`** | 8 | Dedicated Inputs | [cite_start]`ui_in[0]`: UART RX Pin (Bit-bang serial data here).<br>`ui_in[7:1]`: General Purpose Inputs[cite: 3]. |
| **`uio_in`** | 8 | Bidirectional Inputs | [cite_start]`uio_in[4]`: SPI CS_N (Chip Select).<br>`uio_in[5]`: SPI CLK (Clock).<br>`uio_in[6]`: SPI MOSI (Data In)[cite: 79]. |

### B. Standard Outputs (Monitored by Python)
| Signal | Width | Description | Expected Behavior |
| :--- | :--- | :--- | :--- |
| **`uo_out`** | 8 | Dedicated Outputs | [cite_start]Should reflect `tx_reg[7:0] + ui_in`[cite: 22]. |
| **`uio_out`** | 8 | Bidirectional Outputs | [cite_start]`uio_out[0]`: User Interrupt (Goes High on RX valid).<br>`uio_out[3]`: SPI MISO (Data Out)[cite: 87]. |

### C. Whitebox Debug Outputs (Unique to `tb_custom`)
These signals enable "Glass Box" testing, allowing verification of internal states that are usually hidden.

| Debug Signal | Internal Source | Verification Purpose |
| :--- | :--- | :--- |
| **`debug_rx_shifter`** | `rx_shifter` | [cite_start]**RX Data Check:** Confirm the UART byte was physically captured in the shift register before reading it via SPI[cite: 11]. |
| **`debug_rx_bit_idx`** | `rx_bit_idx` | [cite_start]**State Machine Check:** Verify if the RX logic is in Idle (`0`) or Active (`1-10`) states[cite: 17]. |
| **`debug_tx_reg`** | `tx_reg` | [cite_start]**Bus Write Check:** Confirm that an SPI Write command successfully updated the internal 32-bit register[cite: 9]. |
| **`debug_tx_frame`** | `tx_frame` | [cite_start]**TX Frame Check:** Verify the Start/Stop bits and Data bits are correctly formatted for transmission logic[cite: 15]. |
