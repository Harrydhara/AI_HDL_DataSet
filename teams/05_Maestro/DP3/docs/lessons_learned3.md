# Lessons Learned

Some lessons that we learned are that the most practical TinyQV design is one that includes the authentication procedures from ESP32 in order to save a large space area. We also learned that the design generated had not been exactly the design we had brainstormed because ESP32 was not acting like a sole Wi-Fi count sensor, we were trying to implement the timing on the chip instead of inside the desired legacy circuit, and we were not implementing the true SPI design. We also learned that SPI should not be blindly trusted: control and threshold registers should be protected from SPI writes, packets should include a lightweight keyed integrity check, stale Wi-Fi data should expire, and the testbench should verify both valid and invalid behavior. Overall, the design improved by becoming smaller in authority, safer in behavior, and more defensible in terms of security, power, and timing.
