the synthesis is taking forever. if I sleep my pc to come back to it, will it start over, or hang, or i have to restart the whole process?
That is a very practical concern. When running OpenLane (especially inside a Docker container on WSL), sleeping your PC is risky.

⚠️ What happens if you sleep:
The Process Pauses: Technically, the CPU execution stops.
The Risk: When you wake the PC, the Docker daemon or the WSL environment might have timed out. This often causes the flow.tcl script to "hang" or crash because it lost its connection to the underlying file system or system clock.
Restarting: If it hangs, you usually have to kill the process and start over.
🛡️ The Good News: You don't have to start from scratch!
OpenLane has a built-in Checkpoint system. If you have to stop or if it crashes, you can resume from exactly where it left off using the -from flag.

For example, since your previous run successfully finished everything up to Step 18, if you have to restart, you can skip the long synthesis and placement by running:

If you are using a laptop, the only way to keep it running while the lid is closed is to change your Windows Power Settings. Otherwise, the moment the lid closes, the CPU will stop, and the OpenLane flow will pause (and likely crash when you reopen it).

why the tag?




The -tag flag is purely an organizational convenience for OpenLane.

If you run ./flow.tcl -design . without a tag, OpenLane will generate a folder name based on the exact second you pressed enter (for example: runs/RUN_2026.05.07_18.45.10/).

By using -tag FINAL_SIGN_OFF, we are explicitly telling OpenLane to name the output folder runs/FINAL_SIGN_OFF/.

This simply makes it incredibly easy for us to find the exact folder containing our 64MHz deliverables when the run finishes, and it clearly separates it from your existing FINAL_SUBMISSION (40MHz) folder.

It has no impact on the actual physics or routing of the chip! You can run it with or without the tag, whichever you prefer.

Objective: To take your Secure DP#3 optimized RTL design and turn it into a final, manufacturable 
physical layout (GDSII file). 
1. Weekly Milestone Journey 
This phase is structured as a 2-week sprint to ensure a stable foundation for the following 
optimization phases. 
Week 1 (Apr 9-15): Synthesis, Floorplanning, Placement, CTS & Routing 
• Run your final synthesis on the DP3 design. 
• Create your chip's floorplan, including power grid and I/O pin placement. 
• Run the main Placement, Clock Tree Synthesis (CTS), and Routing tools. 
• This is a highly iterative process. You will run the tool, analyze timing, tweak settings, 
and run it again. 
Week 2 (Apr 16-22): Sign-off Verification & Final Tape-out Package 
● Run your final STA, DRC, and LVS checks. 
● Your goal is “DRC/LVS Clean” with zero errors.  
● This is the bar for a manufacturable chip. 
● Package your final GDSII file. 
● Write your final, comprehensive project report covering the entire 16-week journey 
(DP1-DP4). 
2. Deliverables & Submission Guidelines 
Teams must submit their work via a private GitHub repository, granting access to assigned 
mentors and judges. 
Required for DP4 Submission: 
• Final GDSII File: The manufacturable layout of your chip. 
• Sign-off Reports: Clean DRC, LVS, and final STA reports. 
• Final Project Report: A comprehensive report detailing your entire journey from DP1 to 
DP4, including your final PPA metrics, security features, and reflections on the process. 
• GitHub Tag: A final commit tagged as “DP4-Submission”.
