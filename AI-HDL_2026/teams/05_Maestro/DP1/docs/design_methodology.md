# Design Methodology

## Initial Approach
How did you start? What was your overall strategy?

We started by downloading the programs, watching videos and setting up work time meetings. Initially, we had plans to finish the baseline source code by certain dates.

## AI Integration Strategy
How did you plan to use AI tools? What was your prompting strategy?

We planned on using multiple AI programs to write the code and verify the code so we don't have one system agreeing with itself. Each one of use had a different LLM (Claude, Gemini, ChatGPT) that we used. Our prompting strategies included listing all design rules/constraints and providing example templates and previous codes generated by another LLM.

## Design Evolution
How did your design change throughout the process?

It is still changing, and we will update once we have continuous changes. We initially wanted to have a simple UART design, but we decided to change it to a design with a more creative application. We then wanted to do something about changing traffic lights with WiFi, and we settled to interface with an ESP32 WiFi module. Then we realized that we had to use SPI communication and then our chip purpose became a traffic light controller that uses WiFi signals to decide when to change lights at an intersection with an inductive loop fallback in case of no WiFi.

## Key Decisions
What were the major design decisions and trade-offs?

We designed with the goal of making something useful and had to trade-off some of the functionality we think would work well in UART. 

## Verification Strategy
How did you ensure your design was correct?

We used AI tools (other LLMs) to validate our design across source file and testbench. We used Verilator with GTKWave to simulate and verify correctness in our design. Then, we used Yosys to check synthesis. with our mentor for feedback.
