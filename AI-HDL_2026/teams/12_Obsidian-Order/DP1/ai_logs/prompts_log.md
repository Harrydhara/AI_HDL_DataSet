```

Generate complete Verilog code for tqvp_gpio module with exact specs:
- 3 registers at addresses 0x00-0x02 (OUTPUT, DIRECTION, INPUT)
- Synchronous design, active-low reset, no latches
- Combinatorial data_out/data_ready for zero-cycle reads
- Optional input-change interrupt (user_interrupt)
- 32-bit bus with 8-bit GPIO, zero-extended
- Clean, synthesizable code with comments
```

**Response Summary**:
- Generated 150-line Verilog module with:
  - Localparam register addresses (ADDR_OUTPUT, ADDR_DIRECTION, ADDR_INPUT)
  - 3 internal registers: output_reg, direction_reg, ui_in_prev
  - Synchronous always block for writes + edge capture
  - Combinatorial always @(*) for read mux (prevents latches)
  - Interrupt logic detects ui_in changes on input pins only
- Updated README.md with PPA estimates (area, timing, power)
- Code structured for clarity: register defs  sync logic  combinatorial logic

**Action Taken**:
- Created src/tqvp_gpio.v with full implementation
- Verified no latches (all paths assign default values)
- Committed and pushed to GitHub (commit c635060)
- Ready for testbench development (Step 3)

**Design Decisions Made with AI Assistance**:
1. **Direction Masking**: Output only driven when direction[i]=1 using ``uo_out = output_reg & direction_reg``
2. **Input Masking**: Read INPUT_REG returns ``ui_in & ~direction_reg`` (zeros out output pins)
3. **Interrupt Trigger**: Edge detection on any input pin configured as input (XOR with previous state)
4. **Zero-Extension**: 24 MSBs hardcoded to 0 for all reads (`{24'h000000, data[7:0]}`)
5. **Combinatorial Reads**: data_ready and data_out use always @(*) to avoid registered delays

**Context**: After completing CRC-8 implementation, user requested replacing CRC-8 with 2x2 matrix multiplier accelerator for higher complexity score ("complex designs score higher"). Matrix multiplication requires more computational resources (multiply-accumulate) than CRC-8 (shift-XOR), potentially earning maximum innovation points.

**Prompt Summary**:
```
Replace CRC-8 accelerator with 2x2 matrix multiplier:
- 16-bit fixed-point arithmetic (8.8 format: 8 integer bits, 8 fractional)
- Registers: MATRIX_A (0x03), MATRIX_B (0x04), MATRIX_C (0x05), MATRIX_CTRL (0x06)
- 5-cycle pipelined computation: C = A × B
- Test vector: [[1,2],[3,4]] * [[5,6],[7,8]] = [[19,22],[43,50]]
- Keep all GPIO and interrupt functionality
```

**Activities**:
1. **Verilog Implementation**:
   - Replaced CRC-8 registers with 6 matrix registers (96 DFFs total)
   - Implemented matmul_element() function for multiply-accumulate with fixed-point
   - Added 5-cycle state machine (mat_computing flag + cycle counter)
   - Matrix data format: 2 elements per 32-bit word [elem1(16), elem0(16)]
   - Row-based sequential writes/reads with auto-incrementing index

2. **Test Suite Update**:
   - Removed test_crc8_accelerator (CRC-8 tests)
   - Added test_matrix_multiplier_basic (diagonal matrix test)
   - Added test_matrix_multiplier_standard (standard [[1,2],[3,4]] test vector)
   - Fixed-point conversion helpers (to_fixed, from_fixed)
   - ±0.1 tolerance for fixed-point rounding errors

3. **Documentation Updates**:
   - README.md: Updated title, overview, register map, innovation section
   - Added matrix multiply formula, fixed-point arithmetic explanation
   - Updated PPA estimates (~250 cells, ~130 DFFs, 5 mW @ 50MHz)
   - Real-world applications: 2D graphics, neural networks, sensor fusion
   - info.yaml: Changed title and description to matrix multiplier

4. **Register Map Changes**:
   - 0x03: INT_CLEAR → MATRIX_A (write-only, 2 sequential writes for rows)
   - 0x04: CRC_DATA → MATRIX_B (write-only, 2 sequential writes for rows)
   - 0x05: CRC_RESULT → MATRIX_C (read-only, 2 sequential reads for rows)
   - 0x06: (new) MATRIX_CTRL (write-only, write 1 to trigger computation)

**Code Generated**:
- matmul_element() function: 16-bit fixed-point multiply-accumulate
- State machine: 5-cycle computation pipeline
- Matrix registers: a00-a11, b00-b11, c00-c11 (each 16-bit)
- Row indexing logic for sequential access
- 2 new test cases with fixed-point conversion

**Technical Details**:
- **Multiplication**: 16-bit × 16-bit = 32-bit signed product
- **Accumulation**: prod1 + prod2 = 32-bit sum
- **Fixed-point adjustment**: sum[23:8] extracts 16-bit result with 8.8 format
- **Computation order**: c00, c01, c10, c11 (row-major)
- **Timing**: Trigger on cycle 0, results ready by cycle 5

**Innovation Impact**: +12-15 bonus points (complex computational accelerator with multiply-accumulate, higher than CRC-8's +8-10)
